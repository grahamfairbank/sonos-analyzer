## Original report

### Overall assessment

The codebase is small, readable and honest about what it does: the speaker traffic really is limited to the fixed read-only requests in `fetch.py`, the web UI builds all DOM from `textContent`, the downloadable HTML report escapes every value, user-typed addresses are validated as private IPv4, XML parsing is protected against entity bombs by the bundled Expat, and the container runs as `nobody`. The gaps are concentrated in two places. First, the "only private IPv4 on port 1400" promise is enforced only for addresses the user types: addresses that arrive from SSDP replies or from speaker XML are not validated, and `urllib` follows HTTP redirects, so any device on the LAN can steer the analyzer to an arbitrary host, port and path. Second, the web server does not check the `Host` header, so the Content-Type-based CSRF defense can be bypassed by DNS rebinding from a website the user visits, giving that site read access to scan results and the ability to start scans or quit the desktop app. There is also one confirmed correctness bug that will hit real households: a room name containing `&` (or `"`, `<`) makes zone-topology parsing fail, which silently removes all room, pair and home-theater analysis. None of these block a beta, but F1 to F4 and F7 should be fixed before a non-beta 0.4.0.

The reviewer disclosed one side effect: a probe that aborted a POST mid-body made the server fall back to an empty request, which triggered one discovery multicast from the review machine (that behavior is finding F6).

### Checked and fine

- **XSS:** the UI sets every speaker-supplied string via `textContent`, including SVG text and titles and `aria-label`; the HTML report escapes all strings. Verified with a hostile name containing `</td><script>` and an attribute breakout.
- **XML parsing:** Python 3.12's Expat rejects billion-laughs payloads and undefined or external entities; ElementTree never resolves external entities.
- **CSRF without rebinding:** POSTs require `Content-Type: application/json`, so plain forms and no-cors `fetch` are refused; no CORS headers are sent, so cross-origin reads are blocked; `nosniff` and `no-store` are set.
- **Typed addresses:** public IPv4, IPv6, CIDR strings and non-strings are rejected; duplicates removed; capped at 64; the discovery timeout is clamped to 1-15 s.
- **Path handling:** only exact paths are served; traversal attempts return 404.
- **Scan lock:** non-blocking acquire with `try/finally` release; concurrent scans get 409.
- **Desktop idle logic:** heartbeat every 60 s, check every 30 s, 15-minute timeout; `--idle-timeout 0` disables it; shutdown from a worker thread is correct; `print()` is safe in a windowed build.
- **PHY sampling:** rate is the second reading over the measured interval; the counter reset is handled; missing results are skipped.
- **Band and channel math:** 2.4, 5 and 6 GHz conversions, the DFS range and the 80 MHz block table are correct.
- **Signal matrix:** radio-to-speaker matching, per-direction measurements and two-way-only links are correct, and the diagram and matrix agree.
- **CLI:** exit codes, `--quiet`, and the version string match the tag and file names.
- **Docker:** runs as `nobody`, no secrets, `latest` only on full releases, revision label present; the Docker Desktop compose file publishes on 127.0.0.1 only; documented env vars, ports, commands and file names match the code.
- **CI inputs:** the `tag` input and release tag reach shell steps only through an environment variable, not expression interpolation.

### Not covered

- Real speakers: discovery replies, review layouts on S1 or older firmware (a review with a single-speaker root returned nothing in a synthetic test; whether any firmware produces one is unknown), households with more than one Sonos system on a network, satellite map presence, and whether `WifiEnabled="0"` coexists with PHY counters (F10).
- Windows and macOS runtime behavior: port binding (F7), SmartScreen and Gatekeeper flows, the Local Network permission prompt, browser launch.
- A browser-based reproduction of DNS rebinding (F1); the server-side precondition was confirmed, the attack chain was not run.
- The published Docker image contents and the existence of the exact action versions; the reviewer had no network access.
- Load behavior with many real speakers.
